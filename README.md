# Aftof

**English** · [Русский](README.ru.md)

A Windows and macOS app that collects files from many folders into a single one, either by copying
or by moving them.

## Why I built it

After every trip I end up with a dozen folders: phone dumps, date-named folders from the camera,
things people sent me in messengers, downloads from cloud storage. To sort that out I used to open
the folders one by one, select the files, drag them into a shared folder, and then deal with
duplicate names like `IMG_0001.jpg` that exist in three places at once. With ten folders it turns
into half an hour of dull work, and I usually messed something up along the way — a file went
missing or got overwritten.

Aftof does it in one pass: you point it at the folders, see every file in a single list, untick what
you don't need and press one button.

I also work on game engine projects a lot, where the asset folders collect the same kind of mess,
and Aftof helps put those files back in order quickly.

## What it does

- Add several folders at once, either through the picker or by dragging them into the window.
- Show the files from all of them in one list: name, source folder, size, date, thumbnail for photos.
- Narrow things down: search by name, filters by type (photos, video, audio, documents, archives),
  Shift-click to select a range.
- Copy or move the selection into one folder — the mode is a switch right next to the button.
- Show progress you can stop at any point, and a report at the end: how many files were transferred,
  skipped, and which ones failed and why.

Your settings, the destination folder, the theme and the language are remembered between launches.

## What happens to your files

A few things I deliberately made predictable:

- **Duplicate names.** If a file with the same name is already in the destination, you can rename
  the new one (`photo (2).jpg`), skip it, or replace the existing file. The choice is remembered.
- **Subfolders.** Searching inside nested folders is on by default. When transferring, you can keep
  the folder structure or flatten everything into a single folder.
- **Moving across drives.** A file can't simply be renamed onto another volume, so it gets copied
  first, and the original is deleted only after the copy is written successfully.
- **Timestamps.** The modification date is preserved so photos don't lose their order in galleries.
- **Hidden and system files** (`.DS_Store`, `Thumbs.db` and the like) stay out of the list by default.

## Installing

Prebuilt binaries live in [Releases](https://github.com/vladane/aftof/releases):

- macOS — `.dmg`, separate builds for Apple Silicon and Intel;
- Windows — `.exe`, a regular installer that lets you choose the folder.

The app isn't signed with a developer certificate, so the system is cautious on first launch. On
macOS, open System Settings → Privacy & Security and allow it to run; on Windows, click "More info →
Run anyway" in the SmartScreen dialog. There's no analytics and no networking inside: the app only
touches the files you picked yourself.

## Languages

The interface is translated into English, Russian, German, Spanish, French, Portuguese, Chinese and
Japanese. On first launch it picks up your system language; after that you can switch with the globe
button in the top-right corner, instantly and without a restart. Along with the labels it changes the
system folder pickers and the way dates, numbers and file sizes are formatted.

To add your own language, copy `src/shared/i18n/locales/en.ts`, translate the strings, and add the
language code to `LOCALES` and `LOCALE_NAMES` in `src/shared/i18n/types.ts`. TypeScript will point
out any string you forgot.

## Building from source

You'll need Node.js 20 or newer.

```bash
npm install
npm run dev        # run with hot reload
npm run typecheck  # type checking
npm run dist:mac   # .dmg into release/
npm run dist:win   # .exe into release/
```

The Windows installer has to be built on Windows: doing it from macOS requires wine and the result is
unpredictable. The icon is generated by `node build/make-icon.mjs`, and electron-builder turns that
PNG into `.icns` and `.ico` on its own.

The stack is deliberately plain: Electron, React, TypeScript, electron-vite. All file work happens in
the main process (`src/main`), the interface lives in `src/renderer`, and translations and shared
types are in `src/shared`.
